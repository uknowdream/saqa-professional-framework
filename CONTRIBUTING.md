# Contributing to SAQA

Thank you for helping improve the SAQA Professional Framework.

## Contribution principles

- Keep examples practical and reproducible.
- Prefer maintainable automation over clever one-off scripts.
- Include documentation for new capabilities.
- Keep test data safe: never commit credentials, tokens, or private customer data.
- Explain the QA risk or engineering problem a change solves.

## Pull request checklist

- [ ] The change has a clear purpose.
- [ ] Documentation is updated where necessary.
- [ ] Examples are reproducible.
- [ ] No secrets or sensitive data are included.
- [ ] Existing behavior is not unintentionally broken.

## Suggested contribution areas

- Playwright examples
- API contract testing
- Mobile automation flows
- CI/CD integrations
- Reporting utilities
- Test-data factories
- Flaky-test detection
- QA strategy documentation
