# SBOM evidence

The container security workflow generates an SPDX JSON inventory for the exact pinned reference image and validates the minimum SPDX document structure before uploading it alongside the Trivy report.

The validator emits the SBOM SHA-256, document namespace, scanner package count, and validation status. This is a structural sanity check, not proof that the inventory is complete, that every dependency is known, or that the scanner itself is trustworthy. On trusted `main`-branch runs, a separate job downloads the validated SBOM artifact, creates a GitHub artifact provenance attestation, and verifies it. Pull-request and non-main runs do not receive OIDC or attestation-write permissions from that job. The attestation authenticates the build provenance of the file, not the completeness or security correctness of the SBOM. Preserve the raw SBOM and scanner version; review findings and provenance separately.

The general Python environment SBOM is generated by the dependency-security job in `.github/workflows/saqa-ci.yml`. The image SBOM is specific to the pinned Juice Shop training target and is not a production application SBOM.
